# 项目开发规则

## 实施与验证

- 遵守 KISS 和“如无必要，勿增实体”，不为假设的未来需求预建框架或抽象。
- 按当前用户任务裁剪范围，不把“最终重要”当成“现在优先”，不以全面工程清单、局部修复或可开展的工作替代产品主线。
- 改动小而可验证，不顺带重构、升级或扩大功能，保留用户无关改动。
- 沿用已有风格，正确处理错误、资源释放与生命周期。
- 默认在当前分支工作；未经要求不创建或切换分支，不参考或迁移 legacy 分支。
- 不擅自安装工具，或调整工具链版本、平台插件与发布配置。
- CodeGraph 工具可用时，理解或定位代码优先使用它；本项目索引缺失或过期时，允许按需创建或更新本地索引，不将索引和日志纳入 Git。查询结果不足时核对实际源码；工具不可用则正常查阅文件，不自行安装工具。
- 文档改动检查链接、格式和范围；应用改动执行相关分析、测试和构建。后台、网络、权限与生命周期行为需要相应设备验证，范围随本次改动裁剪。
- 如实报告失败和未验证项，不把编译成功当作功能正确。修复 BUG 时补回归测试；不适合自动化则记录复现与检查方法。

## 提交与文档

- 独立任务完成、相关验证结果明确后，主动提醒一次提交，并说明已知失败与未验证项。保存开发成果不等于正式发布或完整验收，不要求先补齐所有未来检查。
- 准备进入下一项独立功能时，如上一阶段成果仍未提交，先提示是否收口；用户已明确延后且没有新的独立成果或范围变化时，不反复催促，不为每个微小改动打断工作。
- 提醒不等于授权；未经明确授权不暂存或提交，当前任务的提交授权不自动延伸到后续任务。
- 提交使用英文 `type(scope): subject`，一个提交一个目的，标题简短且不以句号结尾。
- AI 协助统一在提交正文标注 `Assisted by AI`，不使用具体厂商或模型署名，不猜测邮箱；保留正常 Git 作者信息。
- 文档使用中文，命令、路径、标识符和工具输出保留原文。
- 按职责放置内容，不复制已有说明，不写 AI 自述或操作流水；任务进度留在任务与汇报中，不写进 README。
