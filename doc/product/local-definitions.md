# 节点、策略组、规则与provider的本地定义

在“设置 → 路由与资源”打开代理节点、全部策略组、规则或外部资源，可创建和管理相应定义。本地直接定义与配置、插件提供的同类对象使用同一列表、搜索和详情 renderer，不另设“Local customizations”专区或来源标题。本地可写条目在自身提供编辑、删除操作；运行属性来自当前core，表单字段来自保存的原文。

## 保存位置与入口

表单修改保存在全局“本地自定义”插件中，应用通过角色和随机ID识别它。首次保存成功时创建该插件，默认启用、使用前置合并并置顶；后续保存保留其启停、位置和模式。可在普通插件列表中编辑正文、改名或整体删除。删除后重建会生成新ID；提交表单时，检查打开时的插件ID、正文版本及storageEpoch。

| 分类入口 | 任务 |
| --- | --- |
| 代理节点 | 创建节点；重新打开本地节点，编辑或删除 |
| 全部策略组 | 创建组、查看实际属性；从可写组自身打开完整表单 |
| 规则 | 创建、重开及原位删除本地插件正文中的规则；集合内容与provider定义分别管理 |
| 外部资源 | 创建、重开及删除本地插件正文中的两类provider |

创建和重开流程：

1. 在对应分类使用新建动作，填写类型及字段；节点类型在独立单选页选择后返回原表单。
2. 保存表单，首次成功时建立“本地自定义”插件；后续保存修改同一个插件。
3. 点击对应条目的编辑动作，重新打开捕获的插件原文位置；只读条目只打开属性，不提供编辑、删除。
4. 保存后查看所属工作区的反馈，区分正文保存和运行应用结果。应用失败时保留新正文，从提示的重试动作或原保存入口重试；完整错误由用户点击打开。

插件停用、被覆盖或未参与当前加载时，直接本地定义仍作为所属分类的普通条目管理。查看和后续保存不自动启用原停用内容。同名但身份不同的条目保持各自key，编辑不会因名称相同而转到另一份原文。

## 节点类型与字段

GUI新建提供24种固定type，mihomo解析器另支持包含4种built-in在内的28种type。类型选择为独立纵向分组单选页，点击整行可选择、右侧勾选，采用现有Material主题；选中返回原表单，保留共同字段和未提交输入。

| 分类 | 新建类型 |
| --- | --- |
| 标准代理 | HTTP、SOCKS5、SSH、MASQUE |
| 社区代理 | Shadowsocks、ShadowsocksR、VMess、VLESS、Snell、Trojan、Hysteria、Hysteria2、TUIC、ShadowQUIC、gost-relay、Mieru、AnyTLS、Sudoku、TrustTunnel |
| VPN | WireGuard、OpenVPN、ZeroTier、EasyTier、Tailscale |

每个新建type对应一行，HTTPS／SOCKS5-TLS通过各协议TLS字段设置。direct／dns／reject／rematch沿文本导入、已有定义与mihomo解析器处理，新建范围由上表定义。

表单用文本、数值、布尔、选择和可增删集合覆盖实际依赖的公开Option及有效嵌套分支，表达式和编码字符串保留文字输入。可选值精确区分未设置、false、0与空值，数字标单位，字符串列表映射保留原类型。

新建Tailscale定义时使用独立的相对身份目录。改名、更新、停止或删除定义后，身份目录按协议生命周期保留。保存表单时检查字段和原文修改，加载时由parser构造协议对象；认证与网络连通状态从协议会话读取。

## 策略组与provider

组类型为select、url-test、fallback、load-balance，完整提供公共及专属字段，包括default-selected、tolerance、strategy、hash-key。proxies与use分别编辑，引用保留原声明，循环及依赖检查交内核。

| 类型 | 需要保留的输入结构 |
| --- | --- |
| proxy-provider | http／file／inline；来源、path、interval、过滤、限额、header、health-check、override和payload |
| rule-provider | http／file／inline；domain／ipcidr／classical，yaml／text／mrs；MRS不配classical |

HTTP／file的payload按上游后备内容处理；inline节点复用完整子表单，只改父草稿，保存父表单后才写入文件。header保留字符串列表映射，rule-provider format定义外部编码；RULE-SET作为独立规则引用维护。

GUI中的provider路径为可选相对路径，输入检查拒绝绝对路径、反斜线、盘符、NUL、`..`及无效末段，错误关联对应字段；该检查只判断路径文本。HTTP未填写path时由内核生成缓存路径，显式path及文本导入中的路径沿内核公开Resolve／IsSafePath处理，实际文件访问受平台沙箱约束，见[路径接入](../architecture/core-integration.md#compose-and-android-configuration)。

## 规则

规则覆盖所接入内核公开类型与参数：普通规则为类型／匹配值／目标，MATCH仅需目标；RULE-SET引用provider，SUB-RULE引用子规则集，AND／OR／NOT保留原生条件。PROCESS／UID规则使用Android实际可取得的归属信息。

条件与正则内逗号保留原生字符串，只处理外层字段和参数；新增规则放“本地自定义”插件的rules列表开头，重复项保留原索引，引用保留原合法表达。

[连接辅助入口](connections.md#从连接新增规则)使用同一 core context 中取得的完整域名、域名后缀及非 fake-IP 地址，包含 VPN 和局域网入口，目标为有效全部组与 DIRECT／REJECT。编辑原定义时仍需核对它在插件正文中的记录和位置。

## 重开与原文保留

创建或修改后，表单从插件正文中的原位置读取字段，运行数据另外保留用于查看。

保存只修改目标路径，保留未触碰字段、注释、格式和false／0／空值。provider改名保留相邻顺序，重复规则按索引替换。更早参与合成的同名定义可被后续定义覆盖；“本地自定义”插件正文中出现重名时，拒绝保存并保留输入。

目标使用alias、继承、未知type或超出控件表达范围时，表单显示具体原因并保留原文与草稿。可通过插件正文页编辑该目标；其他独立分支继续按各自路径编辑。局部修改机制见[来源与本地编辑](../architecture/data-and-operations.md#来源与本地编辑)。

## 来源与可写性

| 对象情况 | 阅读与修改 |
| --- | --- |
| “本地自定义”插件中直接写出的定义，ID／revision／epoch和原文路径仍一致 | 打开表单编辑／删除 |
| 远程、内置或生成内容 | 阅读结构化运行属性，密码、令牌等字段隐藏显示 |
| 正文冲突、删除重建或整体恢复 | 禁用原表单保存，草稿仍可复制；从新列表项重新打开 |

写入前同时检查“本地自定义”插件的ID、revision、storageEpoch、完整原文和目标路径是否仍一致。

运行记录只有在provenance精确匹配本地entry ID、revision、section/path时，才与该原文定义合成一项。仅同名、旧revision或缺少provenance不能授予编辑权；没有关联的本地定义仍保留，运行选择、测试和更新仅作用于身份匹配的实际core对象。来源、role和启用状态继续参与合成与写入检查，不转换成列表中的来源徽标、专区或说明。

节点、规则先对完整公开stream关联本地定义，再补入未关联原文，统一搜索、计数和分页；不把全部本地条目追加到运行数据的每一页。分页身份包含native token和本地snapshot，正文变化使旧页失效。运行规则保留mihomo顺序与原始index，未装载本地规则保留原文顺序；顶层本地rules只进入main scope，不进入sub-rules或provider内容页。

provider身份包含kind，定义与下载成员分别处理。本地provider定义可编辑，但其下载节点和规则内容保持只读，不写回缓存、不自动改引用，也不随定义删除下载文件。已保存原文与运行属性分别阅读，密码、令牌等字段隐藏显示。

同一正文版本复用解析结果并检查大小；异步解析完成后核对版本，刷新时保留所选对象，原文已经变化时禁用旧表单保存。原文读取或解析失败使用所属工作区的SnackBar，错误详情由用户打开，列表不为状态说明保留空位。

## 删除本地定义

删除只修改“本地自定义”插件正文中的所选定义，provider下载内容与引用保持各自生命周期。删除当前覆盖的同名项后，下层配置中的定义可能重新生效，确认明确这一后果。

删除已保存但应用失败时，正文和revision已更新，可重试应用该保存结果。结果未确认时，禁用旧表单写入，等重新读取状态后处理。整体恢复后，从新列表项重新打开表单，旧回调不能继续保存。

## 表单布局与校验

复杂协议、组和provider以完整章节组织，宽窗并排相关章节，长证书／表达式／集合按需跨区，窄窗保持明确顺序。布局变化时保留同一Form、Controller、草稿、选区／composing和嵌套记录ID。内嵌子编辑只改父草稿，短规则、命名和单键值保持单列。

校验完整草稿后，按字段名和嵌套记录ID定位第一个错误，展开所在章节并滚动到该字段。折叠和屏幕外字段也参与校验。集合按需构建，列表高度根据所在区域、字号、键盘、安全区及保存按钮占用空间计算。

inline子表单保存后返回父表单，父表单保存时才写入文件。字段错误通过输入框样式及语义表达，提交时定位首错并显示一次SnackBar；字段下不增加错误文字行，也不按候选错误预留高度。输入期间不随每个按键重复提示，修正后清除对应错误状态。

保存中进度留在原按钮内，失败、重试及保存结果使用所属工作区的floating SnackBar。健康状态没有空失败区域，错误出现和关闭不移动正文、工具栏或保存按钮；点击“错误详情”后才打开完整技术内容并复制，动作保持至少48逻辑像素触控范围。窗口高度较小时，标题和保存区采用紧凑布局，保留同一保存控件、草稿、焦点及selection／composing。

真实内容编辑、集合增删、章节展开／收起和类型切换允许按内容重排，语言、窗口、字号、安全区及IME变化按当前约束调整。收起章节释放内部输入焦点；校验仍展开首错章节并定位字段。保存检查字段与局部原文修改；加载时先Compose合成YAML，再交公开parser解析。
