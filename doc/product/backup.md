# 备份、覆盖恢复与系统备份

入口为“设置 → 配置与数据 → 存储与数据 → 备份与恢复”，依次提供“导入备份”和“导出备份”。恢复会整体覆盖当前配置、插件和偏好。

## 备份范围

备份是未加密的 ZIP 文件，包含：

- 完整配置和插件正文、来源 URL，以及正文或来源中的密码、令牌等凭据。
- 保存顺序、当前选择、ID、正文版本、角色、Loon 转换选项和自动更新周期。
- 每个配置的策略选择、客户端模式、外观、语言、主色和 Android 应用访问设置。

外部引用文件、Geo／provider 缓存、日志、运行输入、系统授权、WorkManager 数据库和 Tailscale 身份数据不在备份中。首次隐私提示的显示记录保存在本次安装中，也不随备份迁移。

ZIP 固定包含 manifest 和三个业务文件，正文按原字节保存，包括已保存的无效 YAML。导入时检查版本、条目、大小、CRC、SHA-256，以及配置、插件和偏好内容；损坏、缺项、额外项或超限时拒绝整份文件。格式和大小限制见[归档格式与大小限制](../architecture/data-and-operations.md#归档格式与大小限制)。

## 导出与覆盖流程

### 导出备份

1. 在存储页点击“导出备份”，阅读包含配置正文、来源和凭据的提示。
2. 应用读取同一时刻的配置、插件和偏好文件，生成备份。
3. 在系统文件界面选择保存位置和文件名，确认保存。
4. 等文件写入和关闭完成，阅读应用显示的结果。

取消文件选择会结束本次导出。写入或关闭失败时，应用显示具体错误；保存位置可能已有不完整文件，可在系统文件管理器中检查并删除该失败副本，再重新导出。源业务文件保持原内容。

### 导入并覆盖

1. 需要保留当前内容时，先导出一份备份。
2. 点击“导入备份”，在系统文件界面找到备份 ZIP，**选中该 ZIP 后点“打开”**。
3. 某些 Android 文件界面点击 ZIP 会浏览压缩包内部。此时返回 ZIP 所在文件列表，长按该 ZIP，看到已选中 1 个文件后，再点“打开”（OPEN）。
4. 应用复制并检查选中的 ZIP，随后显示“覆盖应用数据？”摘要。核对配置、插件数量、所选配置及覆盖范围。
5. 确认恢复。空集合会清空当前对应内容；确认后，应用停止原 VPN、局域网服务及 PREVIEW，等待所属 core process 和应用侧 I/O 退出，再替换配置、插件和偏好文件，按运行意图处理恢复后的服务。
6. 阅读恢复结果，分别检查数据是否恢复、连接是否建立、设置与调度是否更新。数据已恢复而连接未建立时，查看错误，再到总览处理启动。

覆盖确认使用本次选中并已检查的文件。检查失败或确认前取消时，旧数据和连接保持；当前配置、插件或偏好文件损坏时，仍可通过导入备份恢复。

## 结果与运行意图

检查文件和阅读确认期间，原连接继续运行。确认恢复后，应用限制其他操作同时修改配置、插件和偏好，停止 VPN、局域网服务与 PREVIEW，并等待原资源及所属 process 退出。服务正在启动、正在停止或尚未确认资源释放时，暂不提交覆盖，保留本次选中的文件。

文件替换完成后，仅恢复原先开启且未被本次取消或停止撤销的功能：VPN按恢复前的接管状态决定；局域网还须满足恢复后的lanProxy插件enabled。原先都未开启时保持停止，不因备份中启用了lanProxy而自行启动。恢复使用备份中的完整配置组合，lanProxy正文及enabled保持恢复值，本机地址重新核对；保存的开启意图不表示当前监听已建立。

| 发生阶段 | 结果应显示的内容 |
| --- | --- |
| 检查或确认前取消／失败 | 数据未恢复，原连接保持 |
| 已停止连接、替换文件前失败 | 文件是否替换，以及连接已停止 |
| 文件替换成功后连接失败 | 数据已恢复，连接未建立及对应原因 |
| 文件替换后设置或调度失败 | 数据已恢复，设置／调度的具体失败结果 |
| 页面等待结束，操作仍在执行 | 显示结果未确认，继续等待该次操作；所用备份文件暂不删除 |

结果摘要使用“已恢复”“连接未建立”等文字；技术详情提供恢复、设置应用、调度或重连返回的完整错误、`cause`、`suppressed`及复制。取消发生在文件已提交之后时，仍显示已经完成的恢复。中断后如何恢复文件见[配置、插件和偏好的恢复事务](../architecture/data-and-operations.md#配置插件和偏好的恢复事务)。

## 界面与lifecycle

存储页按“备份与恢复 → 存储用量 → 数据清理”连续排列，限制最大阅读宽度，横向基础间距为 16 逻辑像素。

| 区域 | 显示和交互 |
| --- | --- |
| 备份动作 | 导入在前、导出在后；选择文件、准备、确认、执行和错误期间保留原行位置，执行时显示进度和可用的取消按钮 |
| 存储用量 | 分别统计配置、插件、设置和内核数据；formatBytes 按 1024 换算，例如 `1.01 MiB / 128 MiB`。超限按整数比较，未知为“—”，读取失败显示错误 |
| 内存记录清理 | 清除近期连接中已结束的记录 |
| 磁盘清理 | 显示 cache.db 和实际 Geo 文件逐项清单；确认后先结束所属 core process，再删除所选文件，分别报告完成项与失败项，当前页面保持打开 |

普通用量与清理确认显示对象和范围；底层统计保留私有路径及精确字节数，失败详情保留原路径和完整错误。无法读取的配置或插件集合仍可通过明确的整集合删除操作清空。

进度、按钮和错误信息显隐时保持原操作位置，过渡见[布局连续性](interaction.md#布局连续性)。点击取消后立即发送请求，并禁用该次取消和退出按钮。已开始的文件读写或临时文件清理结束后，才允许下一次操作。

系统文件选择器暂时遮住应用时，应用保留本次文件和结果，恢复可交互后继续。主动切换任务或离开页面时，不再从原页面发起后续操作。选择或准备阶段取消、超时后，不再使用随后返回的文件；已经提交的恢复继续等待执行结果。

恢复期间保留原页面或显示等待，暂时禁用修改。恢复完成后，旧表单、编辑器和菜单不能继续保存；草稿仍可复制，要继续编辑，从恢复后的条目重新打开。文件授权仅限系统本次选择的URI。

## Android系统备份

API24 及以上的云备份与设备迁移规则包含配置、插件和偏好三个正式文件。缓存、事务文件、调度数据库、正在执行的操作、运行会话及 noBackup 内容不进入该通道；首次隐私提示记录仍属于本次安装。

系统设置、账户、配额、设备和备份服务决定是否执行备份、何时传输及使用何种保护。系统恢复通过 SDK 逐文件回调处理，分别记录每个文件的结果；应用内“导入备份”使用三文件整体恢复。

系统恢复后，应用读取偏好、重新安排周期更新并查询运行状态。VPN 由用户明确启动，或由系统 [Always-on](runtime-and-strategies.md#always-on) 发起。文件同步和系统回调处理见 [Android 归档接入](../architecture/android.md#归档与文件访问)。
