# 诊断、内核查看与资源

诊断入口分布在设置的三个组：

| 入口 | 用途 |
| --- | --- |
| 配置与数据 → 内核运行时配置 | 查看公开GetGeneral配置子集和完整原始响应 |
| 路由与资源 → 代理节点／全部策略组／规则 | 查节点与组属性、规则顺序及规则集内容 |
| 路由与资源 → 外部资源 | 查provider和Geo状态，执行单项更新 |
| 诊断工具 → 内核日志 | 按级别与文字查日志，清空或回到最新 |
| 诊断工具 → DNS工具 | 查询名称／IP、查看响应、清理DNS缓存或fake-IP映射 |

运行中读取当前内核；停止时，需要内核对象的页面按需准备PREVIEW。设置首页读取自身状态，日志读取已有窗口。准备、读取和资源更新各自显示进度与结果。

## 查看范围与共同交互

加载与刷新在已有控件内显示进度；空集合、筛选无结果、数量和分页继续显示真实内容。读取失败、操作失败及重试结果使用所属工作区的floating SnackBar，不在正文插入状态／错误行，也不为候选提示预留高度。用户点击“错误详情”后查看完整错误，返回保留原阅读位置。

分类同时管理[直接本地定义](local-definitions.md)。运行对象与本地原文使用同一renderer、搜索、详情和阅读锚点，不另设本地专区、来源标题或徽标；可写定义在自身提供编辑、删除。仅精确匹配provenance的记录与本地定义合成一项，预览或运行会话结束后，未关联原文仍可管理。搜索保留原始输入和composing，内部身份不作为用户搜索内容，缺少运行数据时不伪造运行属性。

集合与属性按实际空间并排或逐页，初始保留无选择状态，详情由用户选择触发。两区共用所属控制器，窗口拆合保持输入、所选对象及两区阅读位置；集合输入开始后，窄窗保持集合区域，完成输入后仍可继续浏览，工具栏的详情按钮重开缓存选择。Ctrl／Cmd+F进入同一集合搜索；Escape按当前详情、输入和页面的顺序退出。筛选或分页排除所选项目时保留详情并说明其与当前列表的关系，配置、provider或运行会话被替换后，保留原内容供复制，并禁用针对原对象的修改。技术内容按所在区域限制最大阅读宽度，长内容惰性呈现；刷新、分页、解析与重排遵守[集合规范](interaction.md#集合与详情)。

页面记录请求时的配置、provider、内核会话及查询条件；资源更新、来源替换或文件变化后停止使用原分页，并禁用原对象的修改。暂时读取失败与原对象已失效分别显示，同名新对象需重新读取后再操作。已发出的读取返回前不启动同类新读取；页面等待超时先提示未确认，之后仍显示原调用返回的结果。来源或查询变化后，保留原请求的结果并标记为旧结果；原调用返回后，使用最新查询条件发起下一次读取；页面销毁时释放该页保存的响应。

运行配置、资源、节点、规则和日志均可查看并完整复制最近原始响应。未知字段、显式空值及读取错误保持原值；provenance在内部参与关联和可写性检查，不追加来源说明区。格式转换失败时仍保留响应供查看和复制。后续分页核对native token、规则sourceToken及本地snapshot，修改前再次核对捕获的来源。旧运行结果只供查看，针对旧core对象的选择、更新和删除禁用；本地原文的管理另外检查保存身份。

## 节点与规则

代理节点包含主配置、全部proxy-provider成员和未关联的本地直接定义，以名称、类型及实际可读字段搜索。节点与规则均在分页前完成本地关联和统一过滤，不把全部本地条目重复追加到每一页；同名对象按精确身份区分，能力与延迟采用实际返回值。provider下载成员保持只读。

全部策略组列出hidden／GLOBAL及实际属性，属性阅读和本地编辑遵循[定义规范](local-definitions.md#来源与可写性)。日常成员选择、自动意图和延迟测试由[策略任务](runtime-and-strategies.md#策略浏览与选择)统一管理。

运行规则保留mihomo实际顺序与原始index，sub-rules按名称分组；RULE-SET进入对应规则集，可识别Geo引用进入资源。未装载本地规则保留原文顺序，顶层本地rules只进入main scope，不进入sub-rules或provider内容页。新增、修改、删除作用于捕获的直接本地定义及确切路径，重复规则分别定位，复合条件保持原引用语义。

## 规则集内容

domain／ipcidr显示公开DumpMrs导出的规范化运行集合，数量随合并去重变化；inline classical可读取公开payload。远程／文件classical的公开接口只有元数据，完整运行枚举当前不可用；页面说明范围，保存的原文与实际运行规则分别显示，不重读缓存文件来补成运行集合。

页面按页展示内容。Go逐条导出公开对象，AppRuntime执行搜索并保留当前页及必要计数；complete terminal frame返回前不将部分记录标成完整页。来源变化、单条超限及传输中断分别反馈，已有详情保留阅读位置。公开接口内部收集／排序的内存峰值单独测量，接口见[内核资源](../architecture/core-integration.md#rules-providers-and-geo)。

## 外部资源

外部资源按合成声明顺序列出proxy-provider、rule-provider和Geo，保留实际配置、文件及加载数据；未关联的本地provider定义进入同一分类列表，identity包含kind。两类provider的定义与下载内容分别处理，编辑定义不授予下载成员编辑权：

| 来源类型 | 更新行为 |
| --- | --- |
| HTTP | 执行公开更新调用 |
| file | 重新加载／监视所声明文件 |
| inline | 使用正文中的内联内容 |

创建或编辑两类provider进入[本地定义](local-definitions.md#策略组与provider)。

GeoIP、MMDB、GeoSite和ASN分别提供状态查看与单项更新，涵盖缺失或未启用资源。随包数据仅在文件缺失且对应geox-url子键缺省时补入；已有文件、替代名称与后续更新保留，损坏库交正常加载处理。

Geo自动更新按用户YAML的geo-auto-update等字段交mihomo公开RegisterGeoUpdater执行，应用没有独立的Geo自动更新开关或逐库调度。四类手动更新各调用对应公开updater，下载、数据库验证、文件替换和reader管理仍由上游处理。

正常路由依赖缺损库时，mihomo可能触发Fatal并结束core process。应用保留页面、最近错误及已完成保存，由总览提供[恢复操作](runtime-and-strategies.md#内核退出与恢复)；不在应用接入层补下载或修复流程。

provider刷新与Geo自动更新均随实际core context运行，包括VPN、局域网或预览用途。取消手动操作后等待对应公开调用实际返回，进程更换另等原process death。

资源分别显示公开返回的数量、内核时间及文件修改时间，无依据时为未知。文件存在、更新调用结果及当前reader所见内容分别显示。手动更新结果关联受理时的资源与进程，进入后台或换源后仍可查看；新来源同名项不使用旧结果，更新后的列表读取失败也不改变已确认的更新结果。来源材料见[依赖依据](../legal/dependencies.md#公共数据资产)。

## 运行时配置

运行配置显示公开GetGeneral接口的实时只读JSON子集，提供格式化、字面搜索和刷新，不改写返回值。“原始数据”可查看及完整复制包含身份和未知字段的反馈，不限于配置子集。完整合成YAML与平台接管状态由各自接口取得，技术长文保留连续阅读和选择。

从“设置 → 配置与数据 → 内核运行时配置”进入后，可在搜索框查找字段或值。右上角“更多操作”菜单提供“刷新”和当前读取错误的“错误详情”；刷新期间，进度显示在同一菜单按钮内。读取失败保留已有JSON和搜索，SnackBar提供重试与详情；关闭提示后，同一连续失败周期不重复弹出，成功读取后发生的新失败可以再次反馈。点击“原始数据”进入完整响应，复制或返回均不改写配置。

## 日志

日志来自内核真实订阅，支持级别过滤、字面搜索、清空和回到最新。显示过滤作用于客户端，内核默认级别为info。AppRuntime保存唯一历史窗口，最多1000条、正文合计1MiB，仅在默认应用进程内存中；Go只有有界传输queue。容量不足时按整条淘汰，单条超过预算时整条略过并保留已有窗口。正文不脱敏、不截短，传输遗漏与本地略过分别显示。内核停止或异常退出后仍可阅读最近窗口，默认应用进程结束后窗口消失。

从“设置 → 诊断工具 → 内核日志”进入后，可输入关键词或用级别菜单筛选。自动读取或清空失败通过SnackBar提示，搜索框和日志正文位置保持不变；点击“错误详情”查看当次完整原错误。右上角刷新菜单提供“刷新”和当前错误的“错误详情”，读取进度留在同一控件内。同一日志来源、窗口和存储身份下，连续读取失败只提示一次，实际读取成功后发生的新失败可以再次反馈；来源变化后，旧提示及其操作失效。

日志阅读和清空按窗口处理：

- 跟随时滚到最新；退出跟随后，旧记录移除时保留仍存在的可见行及其屏幕位置。
- 保留行可查看并完整复制原始字段；对应记录淘汰时，最近原始响应同时从内存移除。
- 点击清空后，AppRuntime更新窗口身份，以同一内核来源的watermark确定边界；清空前已产生但仍在传输queue或FD中的记录不重新进入窗口，边界之后的新日志继续显示。读取watermark失败时保留具体错误。
- 窗口替换后，旧清空请求仍归原窗口，不能清除新来源的日志。
- 停止后可读最近关闭的窗口；查看、刷新或清空该窗口不启动内核。

订阅与排空机制见[日志与信任材料](../architecture/core-integration.md#logs-and-trust-roots)。

## DNS查询

DNS工具查询当前内核解析器，默认记录类型A，支持A／AAAA／CNAME／MX／TXT／NS／SOA／PTR／SRV／HTTPS／SVCB／CAA；PTR接受IP或DNS名称。输入名称按原值传入，URL样式、路径、端口或空白不作为额外的拒绝条件。编码和DNS报文语法交实际DNS库检查，失败时保留编码或查询错误；响应不改写名称输入或输入法组合文字。

查询使用当前DefaultResolver，可能命中缓存。TUN中的hosts及fake-IP处理另见[连接与DNS验证](../development/verification.md#连接与dns)。DNS关闭时反馈不可用，运行时查询当前内核和网络；停止时按需准备预览。

DNS查询、超时及取消由AppRuntime执行，界面只提交意图并读取操作状态，不因刷新或布局变化自动查询。系统默认DNS与显式nameserver: system的能力分别处理：旧Android版本的原始消息、私人DNS与systemClient组合等不兼容情况显示具体字段和原始错误，不转为公共DNS或明文UDP。接口见[Android系统DNS](../architecture/core-integration.md#android-system-dns)。

| 限制 | 口径 |
| --- | --- |
| 原始名称 | 最多1024 UTF-8字节 |
| 请求JSON | 最多4KiB |
| DNS编码 | label最多63字节，wire name最多255字节 |
| 内核调用／桥期限 | 5秒／6秒；期限触发取消请求，不等于实际退出，该次查询返回前不接受下一次查询 |
| 完整结果 | 至多512 RR、编码256KiB；超限整体失败 |

普通Unicode标签使用IDNA，文本形式的转义由DNS库处理，普通ASCII名称保留大小写；编码后的名称不写回输入。DNS报文校验与取消处理见[DNS接口](../architecture/core-integration.md#dns-and-cache)。

结果摘要显示实际Question的名称／类型、捕获的运行或预览来源、RCODE及本次调用耗时，不用当前输入草稿重写已完成查询。Answer／Authority／Additional各项保留name、type、class、TTL和可复制RDATA。摘要右上角提供“原始数据”／“Original data”，空间不足时另行右对齐，打开“DNS查询原始数据”后查看及完整复制公开DNS消息、查询时的内核和网络标识，以及未知字段。NXDOMAIN与空Answer作为有效结果阅读，耗时对应本次调用；实际消息与错误同时返回时，两者均在错误详情中保留。超限整条拒绝，不保前缀或把整份过大结果放入错误详情。

### 查询与结果流程

DNS工具使用同一自适应Dialog，打开和关闭时保留设置分组排布。查询操作为：

1. 输入“名称或IP地址”，选择记录类型，点击“查询”。
2. 成功后进入同一Dialog的结果页，读取Question、来源、RCODE、耗时和各RR区。
3. 要检查完整响应，点击摘要右上“原始数据”；返回修改可保留名称、类型及输入状态，再明确提交下一查询。
4. 要重读内核状态，点击“刷新内核状态”。该动作读取状态，必要时重试准备预览，查询动作由“查询”单独执行。

输入页和结果页的最大阅读宽度为560逻辑像素，并受当前安全可用宽度限制。Dialog统一处理键盘占用，高度随窗口调整；标题和正文一起在限定高度内滚动，高度较小或字号较大时仍能找到全部操作。名称独占一行，类型、“查询”和“刷新内核状态”按空间排列，更多菜单位于标题栏。“查询”发送当前名称和类型；“刷新内核状态”只读取状态、必要时重试准备预览，不发DNS查询，也不改写保留的Question。等待进度留在原控件内；校验、查询和缓存操作结果使用floating SnackBar，不在输入正文插入状态行或预留详情高度。

| 标题栏更多菜单中的详情入口 | 打开的内容 |
| --- | --- |
| 缓存操作详情 | 保留的缓存清理结果 |
| 错误详情 | 查询或取消失败的结果摘要与完整技术详情 |
| 查看上次查询 | 已与当前草稿或来源不同的保留响应 |
| 查看查询结果 | 当前保留查询响应 |

上述详情项仅在有对应实际结果时出现，更多菜单保留DNS缓存和fake-IP清理动作。查询或缓存失败不自动打开技术Dialog；用户点击SnackBar的“错误详情”或对应菜单项后查看，返回仍保留输入与结果。

错误技术层保留查询、取消或缓存清理返回的错误、`cause`、`suppressed`及原始反馈，并支持完整复制。查询响应和缓存结果分别记录请求时的内核和网络。

查询成功后，同一对话框显示结果页。返回修改时保留名称、类型、选区和输入法组合状态；连续调整窗口、字号或键盘时，保持同一路由和Controller，不重新查询。长RR和原始数据按需呈现并可完整滚动阅读，全部操作均可经滚动找到。输入和结果及时更新，布局过渡不延迟查询或取消。

关闭按钮、系统返回、Escape或遮罩真正退出时，第一frame即禁用工具操作、移除焦点和读屏内容，并结束本次页面查询，取消所属请求；原查询及JNI返回后才允许下一次查询。迟到结果不重开工具，重开不自动查询。返回修改、关闭菜单以及工具自己的确认、原数据或错误对话框不算工具退出。进入后台或网络、配置、存储发生变化时，保留原结果、该次查询或清理返回的错误和请求参数，标记为旧结果；基于旧结果的清理按钮禁用。

## DNS与fake-IP清理

DNS标题栏的更多菜单分别提供DNS缓存和fake-IP映射清理，使用完整中／英标签。DNS缓存采用清扫图标，文字使用onSurface、图标使用onSurfaceVariant；fake-IP采用断开关联图标，文字与图标使用ColorScheme.error。两项不一起标红，具体后果在确认或结果中说明。菜单按内容及可用区域测量，命令项不预留勾选图标位置；长标签按词边界换行，菜单可纵向滚动，触控区域至少48逻辑像素。

| 动作 | 确认、结果与边界 |
| --- | --- |
| 清理DNS解析缓存 | 直接执行，原位等待、防重复；完成表示对应当前缓存清理调用返回，仍在执行的查询可能立即重新写入缓存；清理范围限定为所捕获的当前DNS解析缓存 |
| 清理fake-IP映射 | 一次确认旧地址可能失效、客户端可能需重新解析；覆盖当前IPv4／IPv6及启用时持久池，保留数据库文件；有效池缺失时说明当前为空，两族部分失败如实表达 |

DNS缓存与fake-IP映射分别清理，完成后记录本次调用结果；之后网络变化时，结果保留原状态并注明请求时的网络已变化。fake-IP详情分别列出IPv4／IPv6池是否存在、已清理／未启用／未确认，以及持久池是否启用。公开调用只返回聚合错误、缺少某地址族完成回执时，该族标为未确认。详情保留完整清理响应和未知字段，可重新打开并复制；失败时同时显示清理错误、已发生影响和未确认范围。池状态与并发处理见[公开能力](../architecture/core-integration.md#public-api-boundaries)。
