# 配置页设计依据

本文面向项目维护者，记录已认可的配置页结构与交互，不表示功能已经实现或技术组件已经选定。业务行为以[配置操作](product-requirements.md#配置操作)为准，视觉与适配遵循[通用设计原则](product-requirements.md#通用设计原则)；主导航及其他页面见[应用页面设计依据](home-design.md)，当前能力见 [README](../README.md)。

配置页以正式 Flutter 页面作为后续实现和验证载体，不扩建 HTML 原型，也不据此授权删除原型或迁移其他页面文档。

## 页面任务与范围

配置管理是从总览“配置管理”入口进入的二级页面，以配置列表为主，操作按需展开，不增加主导航入口。策略页不提供配置入口。

本阶段包含远程完整配置导入、选择／切换、更新、重命名、来源修改、正文只读查看与删除，以及本地配置创建、系统文件导入和 YAML 纯文本编辑。

不包含复制／关联配置、自动定时更新、云同步、完整外部资源管理、可视化节点／策略组／规则编辑器、配置历史或持久化草稿。不为本阶段增加筛选、分类、排序系统。

## 列表与操作

远程与本地配置放在同一个列表，不拆类型标签页或独立管理入口。名称是主信息，第二行显示远程来源或“本地配置”，底行将正文时间与更新／编辑、更多操作并排，避免单独留下空荡的操作区。远程时间为“更新于 ……”、本地为“保存于 ……”，不重复类型；未知时间分别显示“更新时间未知／保存时间未知”，不伪造记录，不为本地配置放置订阅流量或到期信息占位。

当前选择用勾选标记、1.5 逻辑像素的主题主强调色描边及无障碍选中语义表达，不再重复“当前选择”文字。描边只表示当前选择，不表示正在接管；保持中性背景与既有圆角，不添加发光或阴影，不改变卡片尺寸、内边距及文字位置。实际接管、旧正文仍在运行、正文不可用及操作失败与选中状态分别表达，不以选中推定运行。正常页面和卡片不提供泛泛的“配置说明／配置状态”弹窗；读取失败保留错误入口，单项错误从更多菜单查看。系统备份规则留在产品与平台文档，不单设常驻说明按钮。状态变化不增加卡片行数或推移操作位置，读取、失败、未知与运行状态的真实性遵循[状态与配置身份](home-design.md#状态与配置身份)。

| 类型 | 行内直接操作 | 更多菜单 |
| --- | --- | --- |
| 远程配置 | 更新 | 重命名、修改来源、查看正文、删除 |
| 本地配置 | 编辑 | 重命名、删除 |

- 点击配置行选择／切换，不增加二次确认；删除仍遵循既有后果确认与运行中限制。
- 两类行内按钮位置和触控区域对齐，各自提供“更新／编辑”的语义标签。本地不显示无意义的更新按钮，也不在更多菜单重复放编辑入口。
- 更新、编辑和更多按钮独立响应，不触发行选择；基本操作不能只能通过长按或滑动发现。
- 管理菜单按需展开，不在列表下方长期铺设操作工作台。处理中的操作提供即时反馈并防止重复受理，不能乐观宣称成功。
- 列表保留稳定保存顺序，更新不重排；类型图标与选中勾号对齐名称首行，槽位随字号适配，长名称自然换行。长名称、窄屏、大字号与深浅主题遵循通用设计原则，不缩小系统字号来塞入内容。

## 添加入口

配置页右上角为“＋”。点击后打开锚定该按钮的弹出菜单，直接列出：

1. 从 URL 导入
2. 从文件导入
3. 新建本地配置

不使用添加底部面板，不另放 FloatingActionButton，不增加中间选择页面；添加菜单不混入已有配置的更新、编辑或删除操作。

### URL 与文件导入

URL 导入完整远程配置，沿用来源隐私、HTTP 风险确认与同来源覆盖规则。修改已有来源的提交按钮明确写“保存并更新”，不是仅保存地址；错误与重试按产品规则表达。命名、重命名与修改来源的输入区使用稳定的期望宽度，并由可用窗口收窄，不随输入长度撑宽对话框或横移按钮。

文件导入成功后直接返回列表，不强制进入编辑器，也不要求再填一次名称。默认名称来自文件名，可随后通过更多菜单重命名，正文可通过行内编辑修改。配置名称不承担唯一身份，同名不自动覆盖已有项。文件读取或保存失败明确报错，不把失败表示成空配置导入成功。

### 新建本地配置

输入名称后进入正文编辑页，预填可编辑的最小直连模板，而不是完全空白。明确说明默认直连、需要自行添加代理与规则，不暗示已经提供代理服务，也不改变客户端已保存的运行模式。首次保存前不在列表创建空记录；未修改模板也可以执行首次保存。

模板的具体 YAML 与 DNS 行为在实施方案中核实，不将候选模板写成已经验证可运行的内容。TUN、监听端口等应用管理字段不重复放进用户模板。

## 正文编辑与只读查看

本地编辑使用独立页面，不嵌入列表，也不先进入资料页再打开第二层正文编辑。顶栏显示配置名称、返回及保存操作；正文提供等宽字体、行号、查找、未保存标记和系统文本选择、复制、粘贴。适配手机宽度的自动换行仅改变显示，不改变 YAML 实际行与正文。

不提供自动格式化、自动补全、多文件工作台或可视化配置表单，不设置“文本编辑器保存 → 外层资料页再次保存”的两层流程。

远程正文采用相同的阅读布局，明确标记“只读”，提供查找和文本选择，不显示保存按钮，不提供转为本地或创建副本入口。来源及正文的隐私要求见[数据真实性与隐私](product-requirements.md#5-数据真实性与隐私)。

## 保存、返回与错误表达

保存不做正文内容检查，也不展示“验证通过”。写入与实际加载是两个结果，完整行为见[配置操作](product-requirements.md#配置操作)。顶栏保存按钮按“保存／保存并应用”的最大自然宽度保留同一槽位，随系统字号适配；运行身份、停止、应用失败或恢复只改变文案与可用状态，不挤动配置标题。

| 情形 | 操作与页面反馈 |
| --- | --- |
| 未运行项 | 按钮为“保存”；写入成功后返回列表，不自动启动或切换 |
| 正在运行项 | 按钮为“保存并应用”；不另弹泛泛确认，展示保存及应用的真实结果 |
| 保存失败 | 留在编辑器，保留内存输入；可重试保存、关闭错误提示继续编辑，或“放弃修改并退出” |
| 已保存但应用失败 | 明确显示“已保存，应用失败”，提供继续编辑或返回列表；不能将此结果称为保存失败，也不提供“放弃保存” |
| 无未保存修改时返回 | 直接返回；未首次保存的新建项不产生记录 |
| 有未保存修改时返回 | 提供“继续编辑／放弃修改”；明确放弃后直接退出，不叠加第二次确认 |

“保留输入”不是另存一份新配置或回滚副本，只是不清空编辑器内存；应用进程结束不保证恢复。退出按钮使用“放弃修改并退出”，不使用容易被理解为结束应用进程的“强制退出”。已经写入的正文不会因为退出编辑器而撤销。

## 实施前技术核实与验收依据

本文不指定编辑器、文件选择组件或配置模型的技术实现。实施方案需核实最小模板及 DNS 行为、编辑组件的大文件与输入体验、系统文件读取和当前记录完整性与并发校验；文件类型、编码、尺寸边界与未知时间的具体呈现需在方案中明确。不能用内核预览充当无资源副作用的保存预检，也不能因现有模型仅支持 URL 而静默缩减本地配置范围。

后续验收聚焦本页用户路径：添加三种来源、行选择与按钮互不误触、远程更新和来源修改、本地单次保存、保存失败重试／放弃、已保存但应用失败、未保存返回及只读查看。核对长文本、查找、键盘与返回、窄屏／大字号／深浅主题；实际文件导入和运行配置重新加载需相应设备验证。文档确认、编译成功或基础测试通过均不等于这些行为已完成验收。
